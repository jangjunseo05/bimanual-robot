## 1. 규칙

**안내 방식**
- 한글로 답한다. 설명 없이 사용자가 해야 할 일만 번호로 쓴다.
- 주행 PC 명령은 코드 블록에 **들여쓰기 없는 한 줄**로 준다. 여러 줄을 복사하면 NBSP가 섞여 `command not found`가 난다.
- 붙여넣는 명령에 `*/` 글롭과 `for … in $(…)`를 쓰지 않는다. 2026-11-01 `*`와 공백이 사라져 빈 압축 파일이 오고 구문 오류가 났다. `ls -t | grep -E "^접두사"`나 정확한 폴더 이름을 쓴다. 결과를 받으면 파일 크기와 시각을 확인한다.
- `init 끝`이라는 말을 그대로 믿지 않는다. 마지막 줄이 `init complete`인지 본다(2026-11-01 `STOP: activation failed`가 끝으로 보고된 적이 있다).

**사용자 말을 받은 뒤에만 실행**
- 실행기 시작(연결하면 토크가 켜진다), `stow`·`stow_right`·`call`(팔 이동), `emergency_torque_off.py`(토크 해제).
- 요청할 때 무엇이 어떻게 움직이는지 적는다. 예: "팔 켜줘"라고 말씀해 주세요. 토크가 켜지고 팔이 약 10초 접힙니다.
- 이 규칙은 차량 주행 규칙과 별개다. 주행 출발은 `CLAUDE.md`의 실차 이동 규칙을 따른다.

**하지 않는 것**
- `jdamr_depart.py prepare`를 실행하지 않는다. 등록 파일이 바뀌지 않았다면 필요 없고, `session-start` code 3을 부른다(6절).
- 실패 1건만 보고 추측으로 코드를 고치지 않는다. 로그·Windows 기록으로 원인을 확인한 뒤 고친다.
- 실패 뒤 로그를 확보하기 전에 다시 돌리지 않는다.
- 커밋·푸시는 사용자가 요청할 때만 한다.

**판정과 기록**
- 성공은 실물로 판정한다(물이 따라졌는지, 컵이 놓였는지). 사용자 육안 보고는 실측 없음을 밝혀 적는다.

**[사용자]**

### 도크 후면 실제 간격

12회차 라이다 기준 0.94~1.19 cm, 각도 -0.3도, `confirmed=true`인데 실물은 상자에 닿아 살짝 밀었다. 라이다 면과 실제 접촉 지점 사이에 1 cm 이상 차이가 있다. 먼저 닿는 부위를 눈으로 보고 후면 외곽 치수(현재 -0.28 m) 또는 도크 기준을 줄자로 맞춘다. 임의 여유를 더하지 않는다. 상자는 고정돼 있지 않아 회차마다 밀릴 수 있다.

### 주방

- 근접 프레임 3장 갱신과 측면 재정렬은 코드 시험만 통과했다. 실차에서 동작이 나오면 기록을 남긴다.
- 책상면 보정(약 -0.72도, -6.7 mm)은 9회차 1회 실측으로 넣은 잠정값이다. 12회차 좌우 1 cm, 14회차 왼쪽 1.0·오른쪽 1.4 cm로 맞는 쪽이다.

## 13. 회차 기록 형식

`PROGRESS.md` 최상단에 회차마다 한 줄씩 남긴다.

```text
- N회차(주문, 미션, 시각): 주방 왼쪽/오른쪽 간격, 좌우 치우침, 측면 재정렬 여부 / 물따르기 reason·run_s / 컵배치 reason·run_s / 도크 drive_link 상태·왼쪽/오른쪽 간격 / 실패 이유 / 손목캠 끊김 횟수
```

전체 성공은 `drive_link=succeeded/complete`이고 실물로 주방 좌우가 맞으며 컵이 놓이고 도크에 들어간 회차만 센다.
